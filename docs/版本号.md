# 版本号的唯一出处

第 142 轮建立的。改版本时**只改这一处**，然后：

```
.\build.ps1 D:\android-ndk-r29
```

`build.ps1` 会把它写进 `app/src/main/jni/Includes/Version.h`
（该文件在 `.gitignore` 里，因为它是**生成物**）。

## 为什么需要它

这份代码里一度有**三个**互不相同的版本说法：

| 位置 | 说法 |
|---|---|
| `app/build.gradle` `versionName` | `3.2` |
| `Main.cpp` 窗口标题 | `Il2CppTool v0.9 | HitMargin` |
| `SelfCheck.cpp` 自检页 | `v0.9` |
| 仓库里的旧包 | `Tool_v0.9.zip` |

自检页那两行的存在意义**就是**「用户报『菜单没反应』时，让我一眼确认他跑的是哪个版本」。
它自己报的是错的版本，于是**这份报告最关键的一栏是假的** ——
用户如实抄给我一份写着 v0.9 的报告，我按 v0.9 排查，而实际代码可能已经差了几十轮。

`build.gradle` 那个 `3.2` 属于 **gradle 那条构建路径**，而本项目实际走
`build.ps1` + ndk-build（`app/build.gradle` 里也接了同一个 `Android.mk`，
所以两条路径都存在）。强行统一它们是另一件事，不在这里做。

## 现状与取舍

- **`build.ps1`（主路径）**：从本文件取版本号，写进 `Version.h`。
  窗口标题和自检页都读它。
- **gradle（备用路径）**：`versionName` 仍是手写的，不参与这里的分发。
  改它不会影响 `build.ps1` 构建出的 so。

选「构建日期 + git 提交」而不是纯版本号，是因为
**这个项目从 v0.9 之后没有再发过版**（`CHANGELOG.md` 也停在 v0.9）。
继续报一个早就过期的版本号，比报日期更糟：日期不会撒谎。
