# 真机验证清单

本轮（以及前几轮）的**所有**改动都只经过**编译 + clang-tidy + CI 编译**验证。
**没有一条在真机上跑过。**

这一点必须先说清楚：本项目是注入进别人游戏进程的库，编译通过只说明类型和语法对，
不说明运行时行为对。很多 bug（竞态、生命周期、GC 时机、投影计算）在编译层面
是完全不可见的。**未经真机验证的修复，可能看起来已经解决了问题，实际没有。**

本清单按「出问题最容易观察到」的顺序排列。请逐条记录**通过 / 失败 / 观察到什么**。

---

## 0. 先打开「自检」页，再做任何别的

工具里新增了**自检**页（和「日志」页同级）。它把「哪些前置条件成立」
一次性摊开：il2cpp API 是否解析、程序集数量、**触摸偏移是否正确**、
ESP 的相机/投影/包围盒是否就绪、当前持有多少 GC 根。

这个项目里很多问题是**静默**的 —— ESP 拿不到相机就只是不画框，
触摸字段偏移错了菜单就完全没反应，用户看不出是哪一环坏了。
自检直接告诉你哪一项失败；具体原因去「日志」页看。

**先做这一步**：如果自检有红色「失败」项，先解决它再往下测，
否则后面很多条会白测。

自检里还有一组「构建开关」条目（Frida 回溯 / JNI 触摸注入 / D 级日志），
它们告诉你**源码里看得到、但你这个构建里没有**的特性，以及怎么启用。
看到代码里有回溯功能却始终没反应，多半就是在这里。

另外自检里有一项「软键盘」—— 它是**所有文本输入的唯一入口**
（搜索框、参数、字段编辑、预设名全靠它）。这一项失败的话，
上面那些输入框全都点不动，而点不动的原因是界面不会告诉你的。

## 0.1. 记录帧率基线

在注入任何东西之前，先记录你目标游戏的：

- 包名、Unity 版本、架构
- 游戏在**不加载本工具**时的帧率基线（连续 3 分钟稳定值）

后面所有性能相关的判断都要和这个基线比。没有基线，「变卡了」只是感觉。

**如果 1.2 明显卡顿，先不要继续往下测**，把卡顿时的日志抓下来（第 7 条），
那是当前最有价值的线索。

> **1.5 / 1.5b 值得单独强调。** 「可用宽度减去固定按钮宽度」这类写法，
> 在开发机上（鼠标、宽屏、默认缩放）永远是正数，看着完全正常；
> 到了窄屏或大缩放才减出**负数**，而 ImGui 不会报错——它画出一个
> 退化的、**点不中**的矩形。正式版没有断言，问题只会表现为「按钮偶尔按不到」，
> 极难联想到是宽度算成了负数。这类缺陷静态看不出来，只能靠换尺寸试。

## 5. Patcher（本项目风险最高的改动）

## 怎么回报结果

失败的话，请一并提供：

1. **「日志」页的完整内容**（点「复制全部」直接粘贴即可）
2. 卡在哪一步（对应编号，比如 `3.2`）
3. 实际现象 vs 期望现象
4. 游戏名 / Unity 版本

有了日志页，大部分问题能直接定位 —— 比如 Patcher 拒绝打补丁时会在
`[E]` 里写明「stub 装不下这个方法（20 字节）装不下（8 字节）」。
